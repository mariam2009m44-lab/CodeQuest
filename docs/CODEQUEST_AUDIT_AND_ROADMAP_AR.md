# تدقيق CodeQuest وخطة التطوير التعليمية والتفاعلية

> تاريخ التدقيق: 9 نوفمبر 2026  
> النطاق: صفحات المسارات، ملفات المناهج، محررات الأكواد، الألعاب، وتجربة الهاتف والكمبيوتر.  
> الحالة: تدقيق مصدر الكود وتغييرات أولية؛ لم يُجرَ اختبار شامل على أجهزة فعلية بعد.

## 1. ملخص تنفيذي

CodeQuest لديها أساس قابل للتطوير: أربعة مسارات لغات، ملفات مناهج عربية، محررات CodeMirror، تشغيل كود عبر خدمة خلفية، وست ألعاب قائمة بالإضافة إلى تجربة 3D. لكن تجربة التعلم موزعة على أكثر من مسار تقني، وبعض المحررات ذات ارتفاع ثابت أو أدوات تحكم محدودة، كما أن الألعاب لا تتبع بعد خريطة واضحة تربط كل مفهوم تعليمي بتحدٍّ مناسب.

لا ينبغي حل ذلك بتغيير الهوية البصرية أو استبدال المحررات عشوائيًا. الأولوية هي توحيد رحلة التعلم، الحفاظ على معرّفات الدروس ومفاتيح التقدم، ثم تطوير المحتوى والأدوات تدريجيًا مع اختبارات تمنع التراجع.

## 2. خريطة المسارات الحالية

| المسار | نقطة الدخول الحالية | مصدر المنهج | الحجم المرصود |
|---|---|---|---:|
| Python | `languages.html → python-welcome.html → python-chapters.html → python-lesson.html` | ملفات `js/chapters/ch*.js` القديمة، مع وجود `json/python_curriculum.json` لمسار الدروس العام | 12 فصلًا و24 درسًا في JSON، مع محتوى Python قديم منفصل |
| JavaScript | `languages.html → levels.html?lang=javascript → lecture.html` | `json/js_curriculum.json` | 8 فصول و26 درسًا |
| C++ | `languages.html → levels.html?lang=cpp → lecture.html` | `json/cpp_curriculum.json` | 7 فصول و23 درسًا |
| Java | `languages.html → java-chapters.html → java-lessons.html` | مصفوفة `CURRICULUM` داخل `java-lessons.html` | 8 فصول و16 درسًا |

### مشكلة بنيوية مؤكدة

Python ليس له مصدر محتوى واحد واضح في رحلة المستخدم: صفحة الدخول تذهب إلى المسار القديم، بينما ملف JSON يحتوي على 24 درسًا منفصلًا. يجب تحديد مصدر معتمد واحد قبل نقل الدروس، مع كتابة ترحيل يحافظ على الإنجازات المحلية والسحابية. لا تُحذف ملفات الفصول القديمة قبل مطابقة كل lesson ID ومفتاح تقدم.

كما أن Java يستخدم منهجًا مضمّنًا داخل HTML بدل ملف بيانات مشترك، والاختبار النهائي/المشروع موصوف في خريطة الفصول بأنه قيد الإعداد.

## 3. تدقيق المناهج

### ما هو موجود

- ملفات Python وJavaScript وC++ تتضمن أهدافًا ومقدمات ومهامًا وتلميحات وأسئلة قصيرة.
- IDs الدروس في ملفات JSON الثلاثة فريدة في الفحص الحالي.
- أعداد الدروس الحالية: Python 24، JavaScript 26، C++ 23، Java 16.
- يوجد تدرج أساسي من الطباعة والمتغيرات إلى الشروط والحلقات والدوال وهياكل البيانات.

### الفجوات التعليمية

1. ليست كل الدروس مصممة كسلسلة تعلم متكاملة من قراءة الكود إلى بناء مشروع.
2. بعض الأسئلة تقيس التذكر فقط، ولا تكشف دائمًا هل يستطيع المتعلم تتبع تنفيذ البرنامج أو تفسير الخطأ.
3. المشاريع الختامية والاختبارات ليست متكافئة بين اللغات.
4. لا توجد خريطة موحدة واضحة تربط كل درس بلعبة أو تحدٍّ قصير يعزز نفس المفهوم.
5. يجب مراجعة صحة كل مثال وناتجه وتشغيله فعلًا، وليس الاكتفاء بوجود نص أو سؤال.

### معيار الدرس الجديد

كل درس جديد أو مُراجع يجب أن يحتوي على:

1. **هدف واضح:** مهارة واحدة قابلة للملاحظة.
2. **سياق قصصي قصير:** مشكلة يفهمها الطفل.
3. **توقّع:** سؤال عن ناتج الكود قبل تشغيله.
4. **تشغيل:** تنفيذ المثال ورؤية الناتج.
5. **استكشاف:** تتبع القيم أو ترتيب الأوامر أو تفسير جزء من الكود.
6. **تعديل:** تغيير صغير مقصود في كود جاهز.
7. **تصحيح خطأ:** خطأ شائع آمن ومقصود مع تلميحات متدرجة.
8. **إنشاء:** مهمة يكتب فيها المتعلم جزءًا من الحل بنفسه.
9. **تحقق من الفهم:** سؤال تطبيقي، لا مجرد حفظ تعريف.
10. **تحدٍّ/لعبة:** نشاط مرتبط مباشرة بمفهوم الدرس.
11. **مراجعة واسترجاع:** سؤال قصير لاحقًا يعيد تنشيط المفهوم.
12. **معيار إكمال:** شروط نجاح واضحة لا تعتمد على مطابقة نصية هشة وحدها.

تُستخدم مراحل PRIMM: Predict, Run, Investigate, Modify, Make، مع تقليل المساعدة تدريجيًا كلما تقدم المتعلم.

## 4. تدقيق محررات الأكواد

### Python القديم

المحرر يحتوي بالفعل على أزرار أحجام ثابتة (220/300/420px) ومقبض تغيير ارتفاع، لكنه لا يوفر وضع ملء شاشة. أُضيف زر ملء الشاشة مع المحافظة على أزرار الأحجام الحالية. يلزم اختبار فتح/إغلاق المحرر، تدوير الهاتف، لوحة المفاتيح، وحفظ الكود على جهاز فعلي.

### Java

كان CodeMirror مضبوطًا على ارتفاع ثابت 300px، و260px في بعض أحجام الشاشات، مع ضبط JS إلى 320px. أُضيفت مساحة أكثر استجابة وزر تكبير/تصغير ملء الشاشة، وتحديث للمحرر بعد تغيير الحجم، وتحسين إدخال اللمس.

### JavaScript وC++

المسار المشترك يستخدم CodeMirror 5.65.16. أُضيف وضع تكبير مساحة المحرر، وإعداد إدخال مناسب للمس، وتحديث بعد تغيير أبعاد العرض، ومفاتيح Tab/Shift-Tab للمسافات البادئة.

### قرار التقنية

لا يُنصح باستبدال المحرر الحالي بـ Monaco على الهاتف؛ توثيق Microsoft يذكر صراحة أن Monaco غير مدعوم في متصفحات الهاتف. CodeMirror 5 يوفّر نموذج إدخال contenteditable على متصفحات الهاتف، لذلك نُحسّن المحرر الحالي بدل فرض محرر غير مدعوم على تجربة الهاتف.

### معايير قبول المحرر

- عرض كامل داخل الحاوية دون قص أفقي للواجهة.
- مساحة كتابة قابلة للتوسيع، ووضع ملء شاشة يمكن إغلاقه بزر واضح أو Escape.
- مؤشر وكتابة وتحديد ونسخ/لصق بلوحة مفاتيح الهاتف.
- عدم فقد النص عند تغيير الحجم أو الانتقال بين خطوات الدرس.
- ظهور أزرار التشغيل وإعادة المثال والنتيجة دون تداخل.
- دعم الوضعين الفاتح والداكن.
- اختبار عرض 360px و390px و768px و1366px على الأقل.

## 5. تدقيق الألعاب

توجد ست ألعاب منفصلة في مركز الألعاب، بالإضافة إلى لعبة 3D بخمس مراحل. لعبة 3D الحالية مفيدة كنموذج أولي لتعليم التسلسل والاتجاهات والتخطيط، لكنها ليست بعد لعبة تعليمية متكاملة واسعة المحتوى.

أُضيفت للعبة 3D تحكمات لمس لتدوير الكاميرا بالسحب والتقريب/الإبعاد بإصبعين، مع زر لإعادة زاوية العرض. يجب اختبارها على أجهزة تدعم WebGL، وعلى الوضع البديل 2D، وعلى متصفحات الهاتف.

### معيار اللعبة التعليمية الاحترافية

- تفاعل أساسي واضح يعمل باللمس من أول مرة.
- أهداف قصيرة، وتعليمات مرئية، ورد فعل فوري على الفعل.
- مستويات متدرجة، مع فتح المراحل بناءً على إتقان المفهوم.
- إمكان التراجع وإعادة المحاولة دون خسارة تقدم غير مكتمل.
- ربط اللعبة بمفهوم محدد: التسلسل، الشروط، الحلقات، المتغيرات، الدوال، أو تصحيح الأخطاء.
- لا تعتمد على 3D ثقيل إذا كان الجهاز لا يتحمله؛ يجب أن توجد تجربة بديلة واضحة.
- احترام إعداد تقليل الحركة، وعدم تشغيل موسيقى تلقائيًا.
- عدم منح XP/نجوم موثوقة من حفظ محلي فقط.

## 6. رحلة التعلم المقترحة

لكل وحدة تعليمية:

**تعلّم مفهومًا → توقّع → شغّل → استكشف → عدّل الكود → العب تحديًا قصيرًا → أنشئ مشروعًا صغيرًا → احصل على تقييم وتقدم موثوق → افتح الدرس التالي.**

يجب أن يكون رابط اللعبة مرتبطًا بمفهوم الدرس، لا مجرد تحويل الطفل إلى مركز ألعاب عام. ولا ينبغي أن تمنح اللعبة مكافأة متكررة بلا تحقق خادمي أو تمنح XP مرتين عند إعادة المحاولة.

## 7. خطة التنفيذ بالترتيب

1. **سلامة البنية والبيانات:** توثيق مصادر المناهج، IDs، مفاتيح التخزين، خرائط Firestore، ومنع تكرار المكافآت.
2. **المحررات:** اختبار Python وJava وJavaScript وC++ على الهاتف والكمبيوتر، ثم إصلاح مشاكل الإدخال والحجم والتركيز والنتائج.
3. **توحيد رحلة Python:** اختيار مصدر منهج واحد بعد مطابقة IDs وترحيل التقدم بأمان.
4. **معيار المحتوى:** اعتماد schema موحد للمراحل التعليمية، ثم تطوير Python كمسار تجريبي أولًا.
5. **المشروعات والتقييم:** إضافة تحديات ومشروعات قابلة للاختبار، مع تقييم يعتمد على الناتج/السلوك وليس regex هشًا فقط.
6. **الألعاب:** ربط لعبة قصيرة بكل مفهوم، ثم تطوير ألعاب لمس فعلية مختلفة في آلياتها، لا تكرار متاهة واحدة بتغييرات شكلية.
7. **اختبار شامل:** تشغيل كل مسار من البداية للنهاية، اختبار حساب جديد وحساب لديه تقدم قديم، واختبار انقطاع الاتصال والعودة.

## 8. الاختبارات المطلوبة قبل الدمج

- تحميل المنهج لكل لغة وعدم وجود IDs مكررة.
- فتح كل درس مباشرة من الرابط ثم الانتقال للدرس السابق/التالي.
- تشغيل أمثلة Python وJavaScript وC++ وJava والتحقق من النتائج.
- إكمال درس، إعادة تحميل الصفحة، والتحقق من استمرار التقدم.
- اختبار مستخدم جديد ومستخدم لديه بيانات محلية قديمة.
- التحقق من عدم منح XP/نجوم مرتين.
- اختبار محررات الهاتف والكمبيوتر ولوحة المفاتيح واللمس.
- اختبار WebGL والبديل 2D في لعبة 3D.
- مراجعة أخطاء Console وطلبات الشبكة.
- لا يُعلن اكتمال 100% دون اجتياز الاختبارات الفعلية.
