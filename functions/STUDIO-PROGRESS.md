# Studio evidence v1, staged and not deployed

Legacy lessonProgress, quizResults, balances and rewards are never modified by the studio workflow. New evidence lives only at users/{authenticatedUid}/studioEvidence/{version}__{lessonId}, with direct Firestore client reads/writes denied. All access uses authenticated callable handlers. It stores phase, revision, UID, lesson/version, completion, server-verified marker, last-submission digest and timestamp, not learner source code or auth tokens.

The immutable version hashes canonical units, explanations and grading parser/checker. Editing these changes the namespace. Prior evidence is retained, never migrated implicitly. A future migration needs an explicit reviewed compatibility mapping; it must not award old achievements or overwrite history. New deployment must ship client version manifest and canonical server files together. Automated consistency test enforces this.

Prediction and explanation are checked against canonical answers. Worked code is server-owned. Practice and transfer require structural concept acceptance and real isolated compiler output for every canonical input case. Client output/completion/UID claims are rejected. Read returns server phase but no source draft. UI begins exercises again for review and shows existing saved state, rather than exposing solutions or inventing recovered code. No evidence means no confirmed saved state. No rewards are granted by this new workflow.

The injected compiler adapter uses Judge0 HTTPS with bounded CPU, wall time, memory, file output and no network. A per-run wall deadline and polling cap prevent indefinite waits. Service errors and malformed responses fail closed. Local protocol tests use mocks; full real compiler browser regressions use loopback development compilers, not this service. Neither proves deployed Judge0/account connectivity. Check actual deployment service resource-policy compatibility before publication.

CAS transactions require matching revision, UID, lesson and version. Identical duplicate submissions can replay the last server result without advancing twice. Rate limits apply to reads and submits. Client queues live only in memory and are not transferred across users. Account changes reload and clear display/session state. Failed submissions remain explicitly unconfirmed with retry; navigation drops the old unsaved in-memory step queue, so users should wait for a saved confirmation before leaving if persistence matters.

Local gates: portable frontend tests, strict verifier tests across all113 canonical sequences, callable auth/schema tests, isolated executor protocol tests, real Firestore rules/Admin transaction emulator, legacy reward/rules tests, identity-switch and saved/unconfirmed browser fixtures, real compiler lesson regression. Production gates still open: deploy functions/rules/client together, authenticated callable and compiler runs in allfourlanguages, logout/account switch/retry on actual deployed system, and confirm old course history remains unchanged. No deployment is authorized by this note.
