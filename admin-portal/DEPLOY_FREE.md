# نشر لوحة CodeQuest على الخطة المجانية

هذا الإعداد ينشر Django كخدمة مستقلة ولا يغيّر استضافة واجهة CodeQuest الحالية.

## البنية

- خدمة Django على Render Free. قد تتوقف بعد 15 دقيقة من عدم النشاط وتحتاج قرابة دقيقة لتبدأ عند أول زيارة.
- PostgreSQL على Neon Free عبر `DATABASE_URL`. تظل البيانات محفوظة ضمن حدود الخطة، لكن قاعدة البيانات قد تتوقف مؤقتًا عند استنفاد حصص الاستخدام.
- Firebase student lookup يبقى مغلقًا. لا تُضف مفاتيح Firebase أو صلاحيات كتابة.

## قبل النشر

1. أنشئ قاعدة PostgreSQL جديدة في Neon على الخطة المجانية فقط.
2. انسخ **Connection string** بصيغة PostgreSQL، واحتفظ به سرًا.
3. في Render اختر **New → Blueprint**، ثم اربط مستودع CodeQuest وحدد ملف `render.yaml`.
4. عند مطالبتك بالمتغيرات السرية، أدخل:
   - `DATABASE_URL`: رابط Neon.
   - `DJANGO_ADMIN_BOOTSTRAP_USERNAME`: اسم مستخدم مالك اللوحة.
   - `DJANGO_ADMIN_BOOTSTRAP_EMAIL`: بريد مخصص لاستعادة الحساب.
   - `DJANGO_ADMIN_BOOTSTRAP_PASSWORD`: كلمة مرور قوية وفريدة لا تستخدمها في أي موقع آخر.
5. تأكد أن الخطة المختارة **Free** قبل تطبيق Blueprint. لا تختَر أي ترقية مدفوعة أو إضافة مدفوعة.
6. بعد نجاح أول نشر، احذف متغيرات `DJANGO_ADMIN_BOOTSTRAP_USERNAME` و`DJANGO_ADMIN_BOOTSTRAP_EMAIL` و`DJANGO_ADMIN_BOOTSTRAP_PASSWORD` من إعدادات الخدمة. أمر التهيئة لا ينشئ حسابًا ثانيًا ولا يغيّر كلمة مرور حساب موجود.
7. افتح رابط الخدمة ثم أضف `/admin/` وسجّل الدخول.

## ملاحظات مهمة

- Render Free يوقف الخدمة بعد 15 دقيقة من عدم النشاط، لذلك قد يكون أول فتح بطيئًا.
- لا تستخدم قاعدة Render PostgreSQL المجانية لهذا المشروع؛ تنتهي بعد 30 يومًا. استخدم قاعدة Neon Free الخارجية.
- Neon Free لها حدود شهرية للتشغيل والنقل والتخزين. عند استنفاد الحصة قد تتوقف قاعدة البيانات مؤقتًا إلى أن تتجدد الحصة. راقب الاستخدام ولا توافق على أي ترقية تلقائية أو مدفوعة.
- Render يضم حدًا شهريًا مجانيًا للاستخدام، وقد تُحتسب رسوم عند تجاوز بعض الحدود مثل نقل البيانات أو دقائق البناء. لتجنب أي خصم غير مقصود، لا تضف وسيلة دفع ولا توافق على أي ترقية أو دفع؛ إذا طلبت المنصة ذلك فتوقف قبل المتابعة وراجع الأمر مع ولي أمرك.
- Render Free لا يوفر Shell/SSH. لذلك تُنشأ قاعدة البيانات وتُجرى الترحيلات ويُجهز حساب المالك عبر أوامر بدء الخدمة.
- لا تشارك كلمة المرور أو رابط قاعدة البيانات في المحادثات أو ملفات GitHub.
- لا تُفعّل `FIREBASE_ADMIN_ENABLED` لمجرد تشغيل لوحة Django؛ لا حاجة إليه لتسجيل دخول المدير أو إدارة محتوى Django.
- صفحة «الطلاب والحسابات» تحتاج قراءة Firebase Authentication. عند تجهيزها لاحقًا، استخدم هوية خدمة بصلاحية `roles/firebaseauth.viewer` للقراءة فقط، ولا تمنح `roles/firebaseauth.admin` أو `Editor`.
- ملخص XP والنجوم والتقدم يحتاج أيضًا صلاحيات Firestore للقراءة فقط. لا تفعّل التكامل قبل مراجعة صلاحيات Firestore والتأكد من عدم وجود أي صلاحيات كتابة. إذا لم تُجهّز الصلاحيات، ستظهر رسالة بأن تكامل الطلاب غير مفعّل.
- صفحة الحسابات تعرض 50 حسابًا في كل دفعة، وتتيح البحث داخل الدفعة الحالية فقط. لا تعرض كلمات المرور أو password hashes ولا تنفّذ تعطيلًا أو حذفًا للحسابات.
- تُستورد المناهج الحالية يدويًا من ملفات JSON عبر الأمر `python manage.py import_curricula --dry-run` أولًا، ثم `python manage.py import_curricula`. الاستيراد ينشئ المحتوى كمسودات، ولا ينشره تلقائيًا. استخدم `--update-existing` فقط إذا أردت استبدال محتوى الدروس الموجود في Django ببيانات ملفات JSON.
- ملفات Python وJavaScript وC++ الحالية تحتوي على بيانات دروس قابلة للاستيراد. ملف Java الحالي يحتوي على عناوين ومعرّفات فقط، لذلك يتخطاه المستورد بدل اختراع محتوى غير موجود.
- أُضيف API عام للقراءة فقط: `/api/v1/curriculum/python/` (واستبدل اللغة بـ `javascript` أو `cpp`). يعرض المسارات والمناهج والدروس المنشورة فقط، مع دعم CORS للواجهة المستضافة على نطاق مختلف. لا يحتاج API إلى بيانات سرية لأنه يعرض المحتوى المنشور المخصص للطلاب.
- وجود API لا يعني أن الموقع الحالي يستخدمه تلقائيًا؛ يجب تعديل واجهة التعلم لاحقًا لجلب المنهج من رابط لوحة Django، ثم اختبار ذلك على استضافة فعلية قبل إزالة ملفات JSON الحالية. لا تغيّر مصدر المنهج في الموقع قبل اكتمال هذا الاختبار.
