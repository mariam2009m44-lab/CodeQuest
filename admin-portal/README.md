# CodeQuest Control Center — Django Admin

لوحة إدارة داخلية مستقلة لإدارة المحتوى التعليمي في CodeQuest. هذه المرحلة تطوّر أساس Django Admin ونماذج المحتوى فقط؛ لا تستبدل الواجهة الحالية أو FastAPI أو Firebase.

## ما أُضيف

- إدارة المسارات والمناهج والدروس مع تحرير العناصر التابعة من الصفحة نفسها.
- بنك أسئلة مرتبط بالدروس، مع التحقق من وجود اختيارين على الأقل وصحة مؤشر الإجابة.
- إدارة الإعلانات مع التحقق من أن تاريخ الانتهاء يأتي بعد تاريخ البداية.
- إدارة المشاريع التعليمية.
- إجراءات جماعية لنشر العناصر المحددة أو أرشفتها.
- بحث وفلاتر وترتيب وعرض صفحات منظم داخل لوحة الإدارة.
- واجهة Django Admin باللغة العربية.
- اختبارات لصلاحيات الدخول والتحقق من صحة المحتوى.

## تشغيل محلي

يتطلب Python 3.11 أو أحدث.

```bash
cd admin-portal
python -m venv .venv
# Windows:
.venv\\Scripts\\activate
# macOS / Linux:
source .venv/bin/activate
pip install -r requirements.txt
python manage.py check
python manage.py migrate
python manage.py createsuperuser
python manage.py runserver
```

افتح `http://127.0.0.1:8000/admin/` وسجّل الدخول بحساب Staff/Superuser.

## الاختبارات

## الأمان

- لوحة الإدارة محمية بنظام Django Authentication وتتطلب مستخدمًا بصلاحية staff.
- لا يوجد تسجيل عام للمديرين.
- عيّن `DJANGO_SECRET_KEY` قويًا وسريًا في بيئة الاستضافة.
- اترك `DJANGO_DEBUG=false` في الإنتاج واضبط `DJANGO_ALLOWED_HOSTS` على نطاق لوحة الإدارة فقط.
- استخدم HTTPS وقاعدة بيانات دائمة ونسخًا احتياطية قبل تشغيلها لمستخدمين حقيقيين.
- لا تضع مفاتيح Firebase أو Gemini أو بيانات حسابات الطلاب في هذا التطبيق.


## صلاحيات فريق الإدارة وسجل المراجعة

بعد تنفيذ ترحيلات قاعدة البيانات، شغّل الأمر التالي لإنشاء مجموعتي الصلاحيات القياسيتين:

```bash
python manage.py setup_admin_roles
```

- **مدير المنصة:** يستطيع إدارة محتوى المسارات والمناهج والدروس والأسئلة والإعلانات والمشاريع، بما في ذلك الحذف، ويستطيع الاطلاع على سجل مراجعة لوحة الإدارة.
- **محرر المحتوى:** يستطيع مشاهدة المحتوى وإضافته وتعديله، ولا يحصل على صلاحية الحذف أو الاطلاع على سجل المراجعة.
- **مالك المنصة (Superuser):** يُنشأ يدويًا عبر `createsuperuser` ويُحتفظ بهذه الصلاحية لحساب المالك فقط.

لإضافة مستخدم إلى دور، أنشئه من قسم المستخدمين والمجموعات في Django Admin ثم أضفه إلى المجموعة المناسبة. الأمر قابل لإعادة التشغيل ويعيد ضبط صلاحيات المجموعتين القياسيتين إلى القواعد الموضحة أعلاه؛ لا تستخدمه إذا كنت قد خصصت صلاحيات هاتين المجموعتين يدويًا.

تُسجّل عمليات تعديل المحتوى والنشر والأرشفة التي تتم من لوحة الإدارة في سجل Django Admin. سجل المراجعة للقراءة فقط، ولا يتيح تعديل السجلات أو حذفها من الواجهة.


## قراءة ملخص بيانات الطلاب من Firestore (اختياري ومغلق افتراضيًا)

أُضيفت صفحة **ملخص بيانات طالب** داخل لوحة الإدارة. الوصول إليها مقصور على مدير المنصة أو مالك النظام، والبحث يتم باستخدام Firebase UID لطالب واحد في كل مرة؛ لا توجد قائمة عامة بكل الطلاب ولا تعديل أو حذف من هذه الصفحة.

تعرض الصفحة الحد الأدنى اللازم للإدارة: الاسم المعروض، XP، النجوم، العملات، المستوى، عدد الدروس المكتملة حسب المسار، وعدد المشاريع المحفوظة. لا تعرض البريد الإلكتروني أو محتوى الأكواد أو تفاصيل المشاريع.

**التكامل غير مفعّل افتراضيًا.** اترك `FIREBASE_ADMIN_ENABLED=false` إلى أن يتم إعداد هوية تشغيل مخصصة بصلاحية قراءة فقط على Firestore، وتحديد `FIREBASE_PROJECT_ID`. يعتمد الاتصال على Application Default Credentials / Workload Identity؛ لا تضع ملف Service Account أو مفتاحًا خاصًا داخل المستودع.

مهم أمنيًا: Firebase Admin SDK يتجاوز Firestore Security Rules. لذلك يجب أن تكون هوية تشغيل لوحة Django مقيّدة بصلاحية IAM للقراءة فقط، وألا تستخدم مفتاحًا إداريًا واسع الصلاحيات. لا تفعّل هذا التكامل قبل مراجعة الصلاحيات الفعلية وبيئة الاستضافة. الصفحة لا تمنح Django حق تغيير XP أو النجوم أو تقدم الطالب؛ هذه البيانات تظل تحت إدارة الخدمات الحالية في Firebase.

## إعدادات الاستضافة (دون إنشاء خدمة)

أُضيف دعم اختياري لـ PostgreSQL عبر المتغير `DATABASE_URL`، وخادم Gunicorn، وتقديم ملفات الإدارة الثابتة عبر WhiteNoise. يظل SQLite خيارًا للتطوير المحلي فقط.

- أمر البناء المقترح: `pip install -r admin-portal/requirements.txt`
- أمر تشغيل الويب: `gunicorn config.wsgi:application --chdir admin-portal`
- أمر الترحيلات بعد توفير قاعدة البيانات: `cd admin-portal && python manage.py migrate`
- فحص الصحة: `/healthz/` ويعيد نصًا بسيطًا `ok`.
- اضبط `DJANGO_ALLOWED_HOSTS` و`DJANGO_CSRF_TRUSTED_ORIGINS` على النطاق الفعلي.
- فعّل `DJANGO_SECURE_COOKIES` و`DJANGO_SSL_REDIRECT` بعد التأكد من أن HTTPS يعمل وأن المنصة تمرر ترويسة البروكسي بشكل صحيح.
- لا ترفع ملف `.env` أو كلمات المرور أو مفاتيح الخدمات إلى GitHub.
